# Месячный план «Пульса» — локальный кандидат

Было: кнопка без обработчика, постоянный `hasAnyPlan=false`, отсутствующий факт
превращался в ноль. Стало: владелец выбирает месяц и сохраняет/редактирует цели
всей организации; форма доступна с клавиатуры, ошибки загрузки и записи видимы.

Цели: лиды, новые ученики, количество оплат, сумма поступлений. Это введённые
владельцем цели, а не сведения об уже полученных результатах. Поступления
не называются признанной выручкой. Суммы сохраняются целыми копейками, количества —
целыми неотрицательными числами; пустое поле отличается от нуля. Хотя бы одна цель
обязательна. Прогноз и филиальные планы в этот кандидат не входят.

Существующая `settings`: ключ `pulse-plan:v1:YYYY-MM`, JSON с targets, revision,
updatedAt, updatedBy (ID auth_users). История каждой сохранённой версии записывается
под `pulse-plan-history:v1:YYYY-MM:revision`; код не изменяет предыдущие версии.
Обновление и история атомарны. Row lock и expected revision предотвращают
молчаливое затирание параллельного изменения (409). Новых схем и миграций нет;
общая таблица settings не даёт FK/SQL-level append-only гарантий для этих JSON.

GET/PUT `/api/finance/monthly-plan` проходят существующие auth, CSRF, access audit
и fail-closed permissions. Дополнительно PUT проверяет роль owner.

Факт лидов: количество зарегистрированных lead_events за источник-месяц по
Europe/Moscow без duplicate_candidate=true. Это наблюдаемая выборка, не доказательство
полноты источника или окончательного удаления всех дублей. Пустая выборка означает
«не подтверждено». Месячные факты новых учеников, количества оплат и поступлений
не подключены: возвращаются null. Старые retired sync counters не используются.
Выполнение = факт/план; нулевой план не даёт деления, перевыполнение видно выше 100%.

Предлагаемый текст D265 (не принятое решение; номер проверен по DECISIONS.md):
«В Пульсе владелец может задавать месячные цели всей организации. История целей
сохраняется, отсутствие цели и отсутствие подтверждённого факта не заменяются
нулём. Поступления отделяются от признанного дохода. Частичное покрытие источника
явно обозначается, прогноз не включается без отдельного определения и проверки».

Production не изменяется. Локальная сборка использует docker-compose.local.yml.

переменных на действующие semantic classes: кнопка имеет видимый фон, форма
прошла сохранение/перезагрузку/редактирование на desktop и mobile. Временные
пользователи и план 2099-12 удалены. Из-за тайм-аутов npm registry последняя
повторная Docker-сборка остановлена; локальный web-образ обновлён проверенным
`build:full` бандлом поверх уже собранного локального web-образа. API использует
успешно собранный образ с новой логикой. Все три Compose-сервиса запущены.
Обычная воспроизводимая сборка по-прежнему: `docker compose -f docker-compose.local.yml up -d --build --wait`.
