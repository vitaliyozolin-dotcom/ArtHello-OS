# D115/D123 — импорт утверждённого справочника финансовых статей

Основание: Виталий передал файл `Атлас ОДДС 01.01.2023-31.01.2026.xlsx`, попросил определить правильный порядок импорта и после описания порядка дал команду «Приступай». Это является утверждением первого справочника и разрешением импортировать его в ArtHello OS. Назначение статей существующим банковским операциям этим решением не разрешено.

## Состав

Источник закреплён SHA-256 `96f03dc6b6b9c0dee391eb9b63cd0f84f27bfc02c924d9d8262ddb34f2b9e71c`; использованы только названия и иерархия строк листов 2023–2026, суммы и иные финансовые строки в репозиторий не переносятся. Утверждённый файл `docs/finance/article-catalog-2026-09-11.json` содержит:

- 148 активных статей: 86 ДДС и 62 ОПиУ;
- направление ДДС, вид деятельности и отдельный отчёт для каждой статьи;
- обезличенные исходные названия для будущего сопоставления истории;
- 12 строк источника, исключённых как итоги, дубли итогов или служебное «неразнесено»;
- 109 уникальных пар «направление + исходное название», каждая из которых либо сопоставлена статье ДДС, либо явно исключена.

Статья описывает экономический смысл. Юрлицо, филиал, счёт, контрагент и сотрудник остаются отдельными измерениями. Персональные зарплатные, дивидендные и комиссионные строки сведены к неперсональным служебным меткам; фамилии из источника в репозиторий не переносятся. Имена собственников не используются как статьи. «Лизинг» вынесен из дивидендов. Связь и интернет объединены. Самозанятые выделены отдельной статьёй для будущих операций, но старый смешанный итог автоматически не разделяется.

## Запись в production

Импорт использует опубликованные D108 API `createArticle` и `approveArticle`. Перед первой записью обязательно создаётся новая резервная копия через owner-only backup API; продолжение разрешено только после появления единственной новой записи `verified_at_creation`.

Импорт повторяемый и выполняется в два этапа: сначала создаются все отсутствующие черновики, затем все целевые черновики утверждаются. Повторный запуск продолжает незавершённый этап, не создаёт дубли и не делает резервную копию, если все 148 статей уже активны. Совпадение имени с другим направлением/видом деятельности, архивная статья, повреждённый каталог, несогласованная ревизия, ошибка авторизации, отсутствие проверенной копии или неполная итоговая сверка останавливают импорт.

Существующие статьи не удаляются и не переименовываются. У несвязанных статей не меняется статус. Банковские операции, суммы, даты, юрлица, ДДС/ОПиУ-разнесение и правила автоклассификации не изменяются. Аудит создания и утверждения выполняется существующим атомарным D108 механизмом для каждой ревизии каталога.

## Защищённый запуск

Первый D115 production-job отказал без видимого кода: shell завершился на ненулевом статусе внутри command substitution до печати уже обезличенного JSON-результата. D117 меняет только workflow и этот документ: закрепляет актуальный parent `2081da08dbfdb6863d3a6c931dfda0a014c1e814`, печатает ограниченный результат до проверки exit code и сохраняет все прежние ограничения импорта.

Фактический D117 результат — `HTTP_403` после успешной проверки production endpoint. Тестовая E2E-учётная запись не имеет требуемого owner-доступа к финансовому каталогу и резервным копиям. D118 не копирует постоянный пароль в GitHub: на gateway он принимает ровно один живой R17-контейнер с source `ff8559254faaedade63a9ee7567a45686d08c13a`, проверяет штатный путь секрета и только в памяти дочернего процесса использует пароль канонического владельца. Значение не печатается и после запуска удаляется из окружения shell.

Фактический D118 результат — `HTTP_401`: bootstrap-пароль живого контейнера больше не совпадает с действующим паролем владельца. По прямому распоряжению Виталия D121 использует одноразовые Environment secrets `ARTHELLO_FINANCE_IMPORT_LOGIN` и `ARTHELLO_FINANCE_IMPORT_PASSWORD`, созданные в защищённой среде `production-ru`. Значения передаются только окружению import-step, маскируются GitHub и не читаются, не печатаются и не сохраняются workflow. Проверки единственного production-контейнера и его точной ревизии сохранены.

One-shot workflow запускается только push в `main`, требует точный заголовок squash-коммита D121, точный список двух файлов, владельца репозитория и успешный Quality первого запуска на том же SHA. Запись выполняется на выделенном `arthello-gateway` runner в Environment `production-ru`. Секреты, банковские строки и идентификатор резервной копии в лог не выводятся. Workflow-count ratchet остаётся 15; существующие workflows не меняются и не отключаются.

## Приёмка

- JSON проходит schema, уникальность, размер, approval и source-coverage проверки.
- Поведенческие тесты подтверждают создание, утверждение, повторный запуск без записи, продолжение черновика и отказ конфликту/архиву до backup.
- Production PASS D123 возможен только после результата workflow: `status=accepted`, `desired=148`, `activeVerified=148`.
- Исторические операции остаются без массового разнесения. Следующий этап — правила сопоставления и ручная проверка предложений на реестре Точки.

## Дополнение D123

По прямому подтверждению владельца добавлены четыре статьи без фамилий и без подмены исторических source aliases: «Оплата управленческих услуг», «Выручка от управленческих услуг», «Оплата организации праздников», «Выручка от организации праздников». За импортом следует отдельный guarded-проход по ООО «АртХелло»: только неразнесённые RUB-поступления `BANK_TOCHKA_API` за 2026-09 с ровно одним явным признаком школы или детского сада. Общий «Атлас», конфликт признаков, списания, частично разнесённые и иные источники остаются без изменения. Перед записью создаётся отдельная verified backup; лог содержит только количества по двум филиалам.
