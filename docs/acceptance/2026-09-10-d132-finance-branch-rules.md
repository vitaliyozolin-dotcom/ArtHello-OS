# D132 — филиальные финансовые отчёты и автоматические правила

## Принято владельцем

- Управленческий учёт начинается 01.09.2026; более ранние записи не разбираются и не входят в отчёты.
- Действующий справочник из 148 активных статей зафиксирован как рабочая база.
- Финансовый отчёт формируется отдельно по каждому филиалу; объединённый режим отключён.
- Автоматическое разнесение допустимо только при однозначном правиле, остальные строки остаются ручными.

## Реализованная граница

API требует `branchId`, проверяет активность филиала и доступ пользователя, затем фильтрует `financial_operations` по `object_entity_id` и дате. Общие остатки счетов юрлица и старые агрегаты без филиального ключа не включаются. Интерфейс при выборе «Все филиалы» показывает требование выбрать конкретный филиал.

Новый импорт Точки не создаёт управленческую операцию до 01.09.2026. Для ООО «АртХелло» однозначное RUB-поступление со школьным признаком получает `BR-ATLAS-SCHOOL`, «Оплата школы» и «Выручка школы»; признак детского сада получает `BR-KINDERGARTEN`, «Оплата детского сада» и «Выручка детского сада». Оба или ни одного признака — без автоматического назначения. Правила работают только при наличии всех четырёх активных статей.

## Проверки

- Поведенческие тесты: граница даты, раздельные филиалы, оба положительных правила и отрицательные ветки.
- Интеграционные ratchets: обязательный филиал в API/UI, применение правила в импорте, сохранение ДДС/ОПиУ и блокировка изменения справочника.
- Требуется перед выпуском: полный v52 test/build, exact-source CI, защищённый release и обезличенная live-сверка операций с 01.09.2026.

Production не изменён этим этапом.
