## Практический порядок загрузки года

1. Подтверждённые классы, предметы, педагоги и назначения.
2. Заполненная недельная сетка расписания и корректные неучебные периоды.
3. «Программы» / «Учебные программы» → «Импортировать XLSX» → класс, предмет, педагог, файл.
4. «Темы и даты»: проверить требуемые часы, распределённые часы, дефицит/резерв.
5. Статусы: черновик → на проверке → утверждена → используется.
6. Учитель ведёт фактическую тему и публикует ДЗ; родитель получает учебные сведения своего ребёнка. Полный внутренний КТП в родительском ответе API не выдаётся.

Проверенный пример: 170 часов математики 2 класса, пять уроков в неделю и четыре заданных периода каникул → 171 слот, 170 распределённых часов, один резерв. Исторические 136 слотов соответствуют четырёхдневной сетке и не являются расчётом текущего пятидневного расписания.

## Обнаруженные ограничения и дефекты

1. **EDU-ATTENDANCE-DATE — посещаемость не готова к ежедневной работе.** В school-app.tsx есть название действия attendance.mark, но нет рабочего элемента ввода/формы. Запись API уникальна по lesson_id + student_id, при этом lessons — недельная сетка без даты занятия. В изолированной SQLite с исходными миграциями две отметки одного недельного урока за 07.09 и 14.09 оставили одну запись со второй датой и статусом. FK проверка прошла. Первую попытку fixture остановили отсутствующие связи; результат воспроизведения получен после создания всех синтетических зависимостей. Нужны конкретная дата/экземпляр занятия, история по датам и рабочий ввод отметок.
2. **EDU-CALENDAR-EDITOR — календарь требует разработчика.** Учебный год 2026/27 (01.09.2026–31.05.2027) и четыре периода каникул зафиксированы в API. Они показываются в UI, но формы смены года/каникул и соответствующих действий API нет. Алгоритм исключает только переданные периоды, не узнаёт все праздники самостоятельно.
3. **EDU-DATED-REPLACEMENT — недельное расписание не равно разовой замене.** Изменение урока меняет недельную запись. Отдельный сценарий замены/отмены на конкретную дату не найден; не объявлять его готовым.
4. **EDU-SCHEDULE-XLSX-UI — массовая загрузка расписания не доступна как обычная кнопка.** Парсер и служебный импорт расписания существуют и проверены; интерфейс предоставляет ручной редактор и копирование дня. Импорт XLSX в «Программах» загружает КТП, а не расписание.
5. **EDU-EVENT-AUDIENCE — аудитория события не ограничивает серверную выдачу.** event.create сохраняет текст audience; GET возвращает все неархивные события без фильтра по классу. Нельзя считать отправку/видимость события только выбранному классу реализованной.
6. **Зафиксированное поведение, не новая ошибка:** темы распределяются при импорте; изменение сетки, отмена и замена не пересчитывают весь год автоматически. Это соответствует прежнему пожеланию Натальи Витальевны не сдвигать темы. Повторный импорт запрещён после ручных тем/ДЗ, чтобы не стереть работу. Отдельного удобного перераспределения оставшейся части года в проверенном UI нет.
