# D-068 · AlfaCRM: выборочная первичная загрузка вместо «синхронизировать всё»

Дата: 2026-09-03

## Решение

Интеграция AlfaCRM в ArtHello OS разделяется на три независимых этапа: **подключение → сопоставление филиалов → выборочная загрузка модулей**.

На этапе подключения система только проверяет v2api и получает список филиалов. Никакие семьи, сотрудники, занятия или деньги в этот момент не импортируются.

После успешной авторизации владелец сопоставляет только нужные филиалы AlfaCRM с действующими филиалами ArtHello OS. Несопоставленный филиал считается исключённым из интеграции.

После сопоставления данные загружаются отдельными модулями. Для каждого модуля обязателен предпросмотр количества записей; импорт разрешён только с теми же параметрами, которые были проверены в предпросмотре.

## Порядок модулей

1. Семьи и дети — только активные клиенты выбранных филиалов.
2. Сотрудники — действующие педагоги; доступы пользователям автоматически не выдаются.
3. Классы и группы — после сотрудников, чтобы сразу связать группы с педагогами.
4. Расписание и занятия — только выбранный диапазон дат; требуется импорт сотрудников и групп.
5. Абонементы и текущие остатки — только по уже импортированным клиентам; загрузка пакетами из-за customer-scoped API AlfaCRM.
6. Оплаты — только с явно выбранной даты перехода до текущей даты.

## Финансовая граница

Платежи AlfaCRM не записываются напрямую в банковский ДДС ArtHello OS. Они сохраняются как отдельный CRM-финансовый снимок для сверки с семьёй и депозитами. Это предотвращает задвоение денег между AlfaCRM и банковскими источниками.

Исторический депозит на произвольную прошлую дату не вычисляется автоматически из текущего остатка: если AlfaCRM не предоставляет исторический снимок баланса на эту дату, ArtHello OS не должна выдавать расчётный остаток за подтверждённый факт.

## Направление данных

Первый production-контур интеграции работает строго **AlfaCRM → ArtHello OS**. Маршруты создания, изменения и удаления сущностей AlfaCRM не используются. Обратная запись может появиться только отдельным решением после сверки идентификаторов, дублей и финансовых границ.

## Авторизация и безопасность

Базовая авторизация соответствует v2api AlfaCRM: `POST /v2api/auth/login` с e-mail и `api_key`, после чего рабочий токен передаётся в `X-ALFACRM-TOKEN`. Список филиалов читается документированным `POST /v2api/branch/index` с фильтром активных филиалов. Поле `X-APP-KEY` поддерживается как дополнительный необязательный заголовок для аккаунтов, где оно применяется, но не подменяет официальную v2api-авторизацию.

Секреты сохраняются только в существующем зашифрованном хранилище интеграционных ключей ArtHello OS. UI после сохранения не возвращает API-ключи пользователю.

Все запросы AlfaCRM проходят через единый сериализованный ограничитель скорости ниже лимита 5 запросов в секунду. Endpoint ограничен HTTPS-хостами AlfaCRM (`*.alfacrm.pro` и `*.sNN.online`), чтобы исключить произвольные исходящие запросы.

## Инкрементальная синхронизация

Автосинхронизация не включается в момент подключения. Сначала конкретный модуль должен пройти первичный импорт и проверку. Только после этого модуль считается готовым к подключению инкрементального расписания по собственному курсору/окну обновлений. До отдельного включения фоновой синхронизации UI не должен создавать впечатление, что она уже работает.
