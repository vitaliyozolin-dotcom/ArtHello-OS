# Правила интеграций

## Общие

- До настройки интеграции изучается полная официальная документация.
- Синхронизация идемпотентна.
- Сырой payload сохраняется неизменяемо.
- Используется поток `Raw → Core → Analytics`.
- Каждая запись получает source, external ID, время чтения и свежесть.
- Повторная доставка не создаёт дубль.
- Удаление и архивирование источника обрабатываются fail-closed.
- Пагинация, rate limit, retry и dead-letter queue обязательны.
- Write-команды отделены от read-sync.
- Внешнее изменение требует белого списка, идемпотентности и повторного чтения результата.

## AlfaCRM

Текущий разрешённый режим — read-only.

Не доказаны:

- полное покрытие всех сущностей;
- членства в группах;
- семейные кандидаты;
- отсутствие пропусков pagination;
- корректное каскадирование stale-parent;
- полнота raw → normalized.

## Банк «Точка»

- Сначала подтверждаются OAuth, счета, остатки и охват юридических лиц.
- Платежи запрещены.
- Начисление не считается движением денег.
- Статус возврата и платёжный статус разделяются.
- Секреты не сохраняются в Git, клиентской сборке или технических логах.

## Финансовая достоверность

При отсутствии операций система не показывает выдуманные:

- нулевой burn rate;
- runway;
- прибыль;
- остаток;
- прогноз.

Вместо этого отображается `NOT_VERIFIABLE` либо конкретная нехватка источника.
