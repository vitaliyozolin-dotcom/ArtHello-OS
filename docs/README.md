# Как работать с библиотекой ArtHello OS

Библиотека — версионируемый слой проектной документации. Она не заменяет рабочую базу данных ArtHello OS и не является хранилищем клиентских данных.

## Поток документа

`INBOX → TRIAGE → DRAFT → REVIEW → APPROVED → EFFECTIVE → SUPERSEDED / RETIRED`

1. Входящий материал остаётся в защищённом исходном хранилище.
2. В GitHub создаётся безопасный черновик либо запись в реестре источников.
3. Владелец проверяет факты и область применения.
4. Утверждающий принимает версию через Pull Request.
5. Операционные факты публикуются в базе знаний ArtHello OS отдельным процессом.
6. Исправление утверждённого документа создаёт новую версию.

## Обязательные правила

- Каждый документ относится только к `ARTHELLO`.
- Другие проектные контуры запрещены.
- Все существенные факты имеют источник и статус достоверности.
- Неизвестное не заменяется догадкой.
- Исторический документ не становится действующей политикой автоматически.
- Ответ сотрудника или AI не публикуется как знание без проверки.
- Секреты и персональные данные в Git не коммитятся.
- Удаление истории решений запрещено; используется замена статуса и новая версия.

## Машинно-читаемая шапка

Новые документы создаются по [шаблону](templates/document.md) и получают YAML front matter.

## Связь с ArtHello OS

GitHub хранит:

- спецификации;
- политики;
- решения;
- шаблоны;
- тесты;
- архитектуру;
- утверждённые справочные документы.

Рабочая база ArtHello OS хранит:

- структурированные знания;
- филиалы, программы и цены;
- сроки действия;
- назначения владельцев;
- разрешения;
- карточки, задачи и события;
- runtime-аудит.
