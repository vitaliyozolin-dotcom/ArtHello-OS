# ArtHello OS — юридический чек-лист данных

Дата фиксации: 26 июля 2026  
Статус: рабочий контрольный список, не юридическое заключение.

Техническое разрешение владельца использовать переданные источники и показать данные в owner-only Sites подтверждено. Оно не заменяет проверку правовых оснований обработки персональных данных, сведений о детях, зарплатных данных и банковской тайны.

## Текущий ограниченный режим

- [x] Sites доступен одной разрешённой учётной записи владельца; группы и публичный доступ отсутствуют.
- [x] Интерфейс закрыт от индексации и не содержит публичных паролей.
- [x] AlfaCRM используется только на чтение.
- [x] «Точка» запрашивает только счета, остатки, клиентов и выписки; платёжных scopes, маршрутов и действий нет.
- [x] Секреты находятся в protected environment и отсутствуют во frontend, Git и отчётах.
- [x] Банковские токены шифруются; номера счетов в интерфейсе маскируются, внутренний ключ счёта хешируется.
- [x] Просмотры чувствительных API и импорт owner-only read-модели журналируются без записи имён, сумм, поисковых запросов и секретов в audit event.
- [x] Сырые персональные и банковские строки не передаются AI CFO; AI CFO остаётся выключен.
- [x] Автоматическое объединение семей по слабому признаку запрещено.
- [x] Зарплатные формулы не активированы как системные правила без отдельного утверждения.
- [ ] После end-to-end проверки перевыпустить временно раскрытые ключи AlfaCRM и «Точки».

## Правовые основания и роли

- [ ] Подтвердить юридическое лицо — оператора персональных данных для каждого филиала и источника.
- [ ] Зафиксировать основание обработки данных сотрудников, родителей, представителей и детей по каждой цели.
- [ ] Проверить тексты договоров, согласий и уведомлений, включая передачу данным техническим подрядчикам.
- [ ] Определить, какие поставщики являются обработчиками/подрядчиками, и проверить необходимые договорные условия.
- [ ] Отдельно подтвердить допустимость хранения зарплатных и банковских данных в выбранных production-средах.
- [ ] Получить профильное заключение по применению 152‑ФЗ, банковской тайне и возможной трансграничной передаче; не считать этот файл таким заключением.

## Минимизация, доступ и аудит

- [ ] Утвердить матрицу ролей по юридическому лицу, филиалу и функции.
- [ ] Включить MFA для владельца и будущих чувствительных ролей, если платформа поддерживает.
- [ ] Запретить массовый экспорт по умолчанию; каждый экспорт журналировать и ограничивать целью.
- [ ] Утвердить перечень обязательных полей для интерфейса и удалить из read-модели всё необязательное.
- [ ] Добавить периодическую проверку журнала просмотров, отказов и изменений доступа.
- [ ] Утвердить процедуру немедленного отзыва доступа у уволенных сотрудников и подрядчиков.

## Хранение и удаление

- [ ] Утвердить сроки хранения отдельно для raw AlfaCRM, зарплатных ведомостей, банковских выписок, audit log и резервных копий.
- [ ] Определить событие начала срока и правовое основание для каждого класса данных.
- [ ] Реализовать проверяемое удаление/обезличивание после истечения срока, включая read-модели и резервные копии.
- [ ] Зафиксировать исключения для бухгалтерских, налоговых, трудовых и договорных обязательств после юридической проверки.
- [ ] Определить порядок исправления, выгрузки и удаления данных по подтверждённому запросу субъекта.

## Инциденты и непрерывность

- [ ] Назначить ответственных за инцидент, юридическую оценку и коммуникацию.
- [ ] Зафиксировать каналы эскалации, сроки реакции, изоляцию, сохранение доказательств и ротацию ключей.
- [ ] Провести учебный сценарий: раскрытый секрет, ошибочный доступ, потеря устройства, массовый экспорт.
- [ ] Проверить backup/restore, шифрование резервных копий и журнал доступа к ним.
- [ ] Вести реестр инцидентов и корректирующих действий без помещения чувствительных данных в общие отчёты.

## Ворота

Текущий owner-only checkpoint допускается только как ограниченная проверка самим владельцем. Расширение аудитории, включение сотрудников, длительное production-хранение, экспорт, AI-обработка или новые банковские действия запрещены до закрытия соответствующих пунктов выше и отдельного решения владельца.
