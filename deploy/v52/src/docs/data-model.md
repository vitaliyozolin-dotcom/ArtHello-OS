# Единая модель данных

## Ядро

- `Party`: физлицо или организация.
- `Person`: сотрудник, родитель, ребёнок, педагог, кандидат.
- `Organization`: юрлицо, подрядчик, поставщик.
- `Unit`: объект, подразделение, класс, группа, проект, ЦФО.
- `Agreement`: договор, приложение, обязательство, срок.
- `Service`: программа, услуга, занятие, питание.
- `MoneyEvent`: начисление, платёж, банковская операция, корректировка.
- `WorkItem`: сигнал, задача, согласование, результат.
- `Document`: файл, версия, подпись, связь с обязательством.
- `AuditEvent`: автор, действие, сущность, время, до/после.

## Ключевые связи

`Семья → ребёнок → договор → услуга → начисление → платёж → банковская операция`.

`Сотрудник → договор → должность → доступ → расписание → задача → начисление зарплаты → выплата`.

`Оборудование → проверка → неисправность → задача → ремонт → акт → оплата`.

## Реализовано в тестовом контуре этапа 2

- `entities` — единая карточка с устойчивым ID, типом, источником, качеством и областью использования;
- `entity_links` — типизированная связь двух карточек;
- `entity_documents` — реквизиты связанного документа без имитации файлового хранилища;
- `entity_merges` — основная и присоединённая карточка, причина и автор объединения;
- `audit_events` — append-only история создания, редактирования, связей, документов и объединений.

Объединение не удаляет строку дубля: она получает статус `Объединена`, а чтение основной карточки включает историю обеих записей.

## Реализовано в тестовом контуре этапа 3

- `tasks` — задача или поручение, источник сигнала, единая карточка ответственного, срок, приоритет, статус, результат, правило повторения и родительская задача;
- `task_checklist`, `task_watchers`, `task_comments` — исполнение и совместная работа;
- `task_approvals` — обязательный вердикт руководителя без перезаписи истории;
- `workflow_documents`, `document_versions`, `task_documents` — документ, его версии и связь с задачей;
- `obligations` — обязательство по документу, срок, владелец и предупреждающий горизонт;
- `notifications`, `escalations` — адресный сигнал и отдельная управленческая эскалация.

Завершение задачи допускается только после чек-листа, подзадач и обязательного согласования. Повторяющаяся задача создаёт следующую запись только после подтверждённого результата.

## Реализовано в тестовом контуре этапа 4

- `finance_accruals` — обезличенные начисления, оплаты и задолженности по контурам;
- `finance_budgets` — отдельно маркированный тестовый бюджет и его допущение;
- `finance_forecast_items` — платёжный календарь, вероятность и прогнозный остаток;

Денежные суммы хранятся целым числом копеек. Запись ОДДС является фактом загруженного XLSX; `BANK-TEST-*`, бюджет и ОПиУ-проекция не выдаются за подключённый банк или утверждённый управленческий отчёт.
