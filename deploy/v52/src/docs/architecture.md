# Архитектура ArtHello OS

Текущий тестовый контур — модульный монолит на Sites. Интерфейс, API и D1 разворачиваются одной воспроизводимой сборкой. Реальные интеграции пока не включены.

## Слои

1. Персональный интерфейс по роли и области ответственности.
2. Доменные модули на общей системе идентификаторов.
3. API действий, прав и аудита.
4. D1 для единых карточек, задач и процессов, согласований, уведомлений, метаданных и версий документов, решений приёмки и журнала действий.
5. Адаптеры источников только на чтение; затем очередь сверки и конфликтов.

## Неподвижные правила

- одна сущность создаётся один раз;
- входящие данные имеют `source_system`, `source_record_id`, `import_batch_id`;
- исправление добавляет новую версию и не уничтожает оригинал;
- критичное событие получает audit event;
- реальные секреты не попадают в репозиторий или тестовый snapshot;
- микросервисы не вводятся до доказанной необходимости.

## Текущие границы

Финансовые XLSX прочитаны локально и преобразованы только в агрегаты. Карточки семей, сотрудников, договоров и учебных событий синтетические. На этом этапе интерфейс доказывает архитектуру и сценарии, но не является production-системой.

Правило `CONTRACT_EXPIRY` идемпотентно: `automation_key` задачи и `dedup_key` уведомления не допускают повторной записи одного сигнала. Полноценный планировщик появится в центре интеграций; сейчас правило выполняется безопасно при инициализации закрытого тестового контура.
