# Интеграции

## Правило статуса

Статус «Подключено» ставится только после проверенной передачи данных. Сохранённые параметры, банковский ключ и успешная проверка доступа только для чтения сами по себе не означают, что импорт операций включён. Файловая загрузка также не считается постоянным подключением.

## Банковские подключения

Альфа-Банк заменён на Т‑Банк. AlfaCRM остаётся отдельной системой продаж и не относится к банковскому подключению.

Т‑Банк подключается собственником по официальной схеме:

1. В Т‑Бизнесе открыть «Интеграции» → «T‑API» и выпустить токен с доступами «Информация о счетах компании» и «Информация об операциях компании».
2. Администратор сервера должен задать подтверждённый статический исходящий IP в `TBANK_EGRESS_IP`. Мастер показывает кнопку копирования только для корректного публичного IPv4/IPv6 из этой настройки. Без неё сохранение и проверка Т‑Банка блокируются. Входящий адрес сайта `188.225.38.55` не доказывает адрес исходящих запросов и не должен добавляться в белый список без подтверждения хостинга. IP компьютера или браузера также не подходит; можно указать до девяти адресов.
3. В ArtHello OS выбрать существующую карточку юридического лица, подтвердить, что при выпуске токена были отмечены только два указанных права чтения без доступа к платежам, ввести токен и запустить проверку.
4. Система запрашивает только список счетов и короткую выписку до десяти операций за семь дней. Номера счетов и операции не сохраняются, платежные методы не вызываются. Эта проверка доказывает только то, что ArtHello OS выполнил две операции чтения; T‑API не сообщает приложению полный состав прав токена, поэтому подтверждение собственника обязательно.

Если токен не используется 90 дней, Т‑Банк отключает его; при регулярном использовании он продолжает действовать. Первичные источники: [выпуск токена](https://developer.tbank.ru/docs/intro/manuals/self-service-auth), [информация по счетам](https://developer.tbank.ru/docs/products/account-info), [метод списка счетов](https://developer.tbank.ru/docs/api/get-api-v-4-bank-accounts), [метод выписки](https://developer.tbank.ru/docs/api/get-api-v-1-statement).

Для Точки собственник вводит один ключ и выбирает карточку юридического лица. Если банк возвращает несколько компаний, браузер получает только их названия и короткоживущие одноразовые идентификаторы выбора. Каждый такой идентификатор на сервере связан с точной компанией, отпечатком ключа, собственником и карточкой юрлица; он действует пять минут и не может быть использован повторно. Поэтому изменение порядка компаний в ответе банка не приведёт к привязке другого юрлица. Служебный код выбранной компании остаётся внутри серверной границы. После выбора проверяется только доступ к счетам. Выписки и операции Точки пока не импортируются.

## Доступ и защита ключей

- Раздел закрывается и в интерфейсе, и в API, если собственник снял у пользователя разрешение «Интеграции».
- Разрешение на сам раздел не открывает весь каталог. Канонический собственник видит все подключения; остальные пользователи видят и изменяют только интеграции, назначенные их роли или конкретной учётной записи. Запуски, журналы, конфликты и сохранённые параметры фильтруются тем же правилом.
- Все изменяющие запросы требуют действующую сессию, совпадающий источник страницы и CSRF-токен.
- Настройка, проверка, приостановка и удаление сохранённых банковских ключей доступны только каноническому собственнику.
- Ключи шифруются AES‑GCM с отдельным ключом окружения `INTEGRATION_CREDENTIALS_KEY`. В открытом виде они существуют только на время запроса к банку.
- Ключи, коды компаний, номера счетов и операции не возвращаются в API, интерфейс, аудит или журнал. Служебный код выбранной компании Точки хранится только на сервере, чтобы связать зашифрованный ключ с выбранной компанией. Ошибки банка очищаются от тела ответа.
- Банковский ключ хранится в отдельном контуре чтения и не может автоматически использоваться будущими платёжными адаптерами. Замена или удаление ключа меняет его служебное поколение. Поздний ответ банка фиксируется только при совпадении поколения; запуск, журнал, статус и аудит записываются одной транзакцией.
- Изменение настроек банковского подключения также создаёт новое служебное поколение, поэтому начатая до изменения проверка не сможет записать устаревший результат. Обычная настройка источника, статус подключения и запись аудита тоже сохраняются одной транзакцией.
- Удаление ключа из ArtHello OS удаляет только локальную зашифрованную копию. Чтобы ключ перестал действовать, собственник должен отдельно отозвать его в Т‑Бизнесе или личном кабинете Точки по официальной инструкции.
- Адреса обычных интеграций принимаются только по HTTPS и без логина, пароля, параметров запроса или якоря. Ключи и подписи передаются отдельным защищённым полем, а не внутри URL.

## Журнал и конфликты

Журнал показывает понятный номер запуска, источник, результат, счётчики и человеческое описание контрольной точки. Служебные идентификаторы, названия событий и ссылки на внутренние записи в основной интерфейс не выводятся.

Конфликт не закрывается автоматически. Нужны осмысленное решение и проверяемое доказательство: документ, ссылка, дата сверки или номер акта. Шаблонная строка `CONTROL:EVIDENCE:*` отклоняется сервером и не считается доказательством.

## Обновление каталога

Замена старого банковского подключения Альфа‑Банка на Т‑Банк выполняется однократной версионированной миграцией при инициализации схемы. Читающий запрос центра интеграций не содержит очистки старых записей. Идентификаторы новых запусков используют полный случайный UUID, чтобы параллельные проверки не пересекались.
