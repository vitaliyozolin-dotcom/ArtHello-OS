# Безопасность входа в электронный дневник

`POST /api/school-sso/exchange` остаётся публичным только для серверного обмена
одноразового PKCE-кода. Маршрут принимает исключительно `application/json`, требует
числовой `Content-Length` от 1 до 4096 байт и отклоняет лишние поля до обращения к
коду обмена. При наличии `Origin` он должен в точности совпасть с настроенным
`SCHOOL_PUBLIC_ORIGIN`; сама настройка должна быть чистым HTTPS-origin.

Приложение ограничивает источник шестьюдесятью попытками в минуту и одной одновременной
попыткой с аварийной арендой на 5 секунд. Квота рассчитана на общий IP школьного
сервера, а не отдельного браузера. Окно и аренда захватываются одним условным D1
UPSERT. В таблице хранится только purpose-separated SHA-256 псевдоним источника;
исходный IP не записывается. В Cloudflare источником служит заменяемый на доверенном
edge заголовок `CF-Connecting-IP`. Если Node/Miniflare публикуется через отдельный
reverse proxy, тот обязан удалить входной пользовательский `CF-Connecting-IP` и
установить фактический адрес клиента. Edge/WAF rate limit рекомендуется как второй
слой, но приложение не зависит от его наличия.

Production runtime получает `SCHOOL_PUBLIC_ORIGIN`, `SCHOOL_DIARY_SYNC_URL` и
`SCHOOL_DIARY_ALLOWED_ORIGINS` явно. `CENTRAL_ACCESS_SECRET` передаётся через
`CENTRAL_ACCESS_SECRET_FILE`. При отсутствии или ошибке конфигурации код не
выдаётся и не обменивается; резервных адресов и кодов нет.

Возврат неавторизованного пользователя на центральную форму входа строится только
из проверенного `ARTHELLO_PUBLIC_ORIGIN`, а не из внутреннего адреса запроса за
reverse proxy. Оба публичных origin должны быть чистыми HTTPS-origin без пути,
параметров, фрагмента или учётных данных; некорректная настройка закрывает вход.
