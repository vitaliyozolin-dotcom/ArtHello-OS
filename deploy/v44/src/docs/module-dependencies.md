# Зависимости модулей

| Поставщик | Потребитель | Данные | Сбой и восстановление |
|---|---|---|---|
| Продажи | Клиенты | лид, источник, оффер, согласия | запись остаётся во входящих, повторная привязка идемпотентна |
| Клиенты | Договоры | семья, ребёнок, услуга | запрет начисления до разрешения конфликта |
| Договоры | Финансы | обязательство и график начислений | сигнал и задача финансовому контролёру |
| Банк | ДДС / ОПиУ | подтверждённая операция | очередь синхронизации, без выдуманного зелёного статуса |
| Сотрудники | Зарплата / расписание / доступы | единый employee_id | увольнение отзывает доступ, история сохраняется |
| Проверка безопасности | Задачи | неисправность, объект, важность | ручная эскалация при недоступности задач |
| Единые карточки | Задачи | `employee_id` ответственного и наблюдателей | создание блокируется при неизвестном или объединённом ответственном; повтор после сверки справочника |
| Документы | Обязательства | `document_id`, срок действия, владелец | правило не создаёт задачу без документа; исправление добавляет версию |
| Обязательства | Задачи | сигнал истечения, срок и владелец | идемпотентная автозадача по `automation_key`; повторный запуск не создаёт дубль |
| Задачи | Уведомления | статус, результат, получатель | при ошибке переход не выдаётся за успешный; действие можно повторить |
| Задачи | Эскалации | задача, уровень SLA, получатель | открытая эскалация остаётся видимой руководителю до отдельного закрытия |
| Задачи | Документы | `task_id` ↔ `document_id` | отсутствие документа возвращает 404; задача сохраняется без ложной связи |
| Продажи | Финансы | `lead_id` → `accrual_id` → `payment_operation_id` | операция без подтверждённого источника помечается `SYNTHETIC_SALES_TEST`, а не банковским фактом |
| Клиенты | Продажи | семья, ребёнок, договор, услуга, LTV и риск | риск объясним, не меняет статус клиента автоматически; менеджер фиксирует решение отдельно |
| Контент | Продажи | publication_id, click_id, campaign_id, lead_id | отсутствие реального источника маркирует атрибуцию как синтетическую, связь не пропадает |
| Контент | Финансы | contract_id, payment_operation_id, revenue_minor | выручка считается только при существующей финансовой операции; охват не заменяет деньги |
| Программы | Обучение | program_id, версия, ожидаемый результат | занятие остаётся связано с применённой версией; новая версия не переписывает результат |
| Сотрудники | Обучение | teacher_entity_id, назначенная группа, замена | педагог не меняет журнал чужой группы; замена хранится отдельно |
| Обучение | Семья | student_id, progress_id, feedback_id | родительский scope отсекает чужие семьи; медицинские сведения не передаются |
| Отзыв семьи | Задачи | feedback_id, recommendation, automation_key | повторное действие возвращает существующую методическую задачу |
| HR | Единые карточки | candidate_entity_id, employee_id | увольнение деактивирует карточку, но не удаляет ID или историю |
| HR | Документы | employee_id, contract_id, position_id | сотрудник не считается оформленным без договора и должности |
| HR | Задачи | employee_id, onboarding task | адаптация создаётся идемпотентно; увольнение не удаляет выполненные задачи |
| HR | Финансы | employee_id, rate_minor, payroll_operation_id | тестовая выплата помечена `SYNTHETIC_HR_TEST` и не подменяет ведомость |
| HR | Доступы | employee_id, system, role, status | offboarding отзывает все доступы; повтор безопасен и история остаётся |
| Юридический модуль | Единые карточки | party_entity_id, owner_entity_id | неизвестная сторона или владелец не скрывается и требует сверки реестра |
| Юридический модуль | Документы | contract_id, stable_id, version | новая версия добавляется append-only; отсутствие обязательного документа создаёт сигнал |
| Юридический модуль | Финансы | contract_id, limit_minor, spent_minor | превышение лимита видно до новой оплаты, но не объявляется нарушением автоматически |
| Юридический модуль | Задачи | check_id, automation_key | один сигнал создаёт одну задачу; решение требует доказательства |
| Закупки | Юридический модуль | supplier_id, contract_id | предложение без договора не превращается в заказ |
| Закупки | Склад | order_id, delivery_id, accepted_quantity | остаток возникает только после приёмки; отрицательный остаток блокируется |
| Склад | Имущество | item_id, asset_id, serial_number | серийный объект связан с номенклатурой и движениями |
| Имущество | Задачи | maintenance_id, automation_key | одна задача на плановое обслуживание, результат связывается с актом |
| Закупки | Финансы | order_id, document_id, payment_operation_id | синтетическая оплата маркируется и раскрывается до договора, акта и ОПиУ |
| Закупки | Питание | request_id, supplier_id, delivery_id, product_id | партия возникает только после приёмки; реальный WMS не имитируется |
| Питание · партия | Производство | batch_id, expires_at, remaining_quantity, recipe_id | просроченная или исчерпанная партия не должна поступать в выпуск; списание ниже нуля блокируется |
| Питание · ТТК | Производство | recipe_id, version, ingredients, yield_portions | изменение нормы фиксирует новую версию и основание |
| Питание · производство | Отгрузка | production_id, actual_portions, document_id | отгрузка раскрывается до потребления, возврата и списания |
| Питание | Финансы | project_id, cost_center_id, revenue_operation_id, cost_operation_id, labor_minor | синтетические операции отделены от банка; прибыль учитывает продукты и смены |
| Проверка кухни | Задачи | check_id, violation, evidence, automation_key | один незакрытый сигнал создаёт одну задачу |
| Объекты | Безопасность | object_entity_id, система, схема, журнал, ответственный | неизвестный объект не скрывается и требует сверки реестра |
| Безопасность · проверка | Задачи | check_id, fault_id, severity, evidence, automation_key | один дефект создаёт одну задачу; SLA считается по тяжести |
| Безопасность | Подрядчики | equipment_id, contractor_id, fault_id, repair_id | работа связана с неисправностью и договорным контуром подрядчика |
| Безопасность | Документы | repair_id, act_document_id, result | ремонт без результата и акта нельзя завершить или оплатить |
| Безопасность | Финансы | repair_id, act_document_id, payment_operation_id, cost_minor | синтетическая оплата отделена от банка и раскрывается до акта |
| Ремонт | Следующая проверка | repair_id, equipment_id, completed_at, scheduled_at | новая дата считается от завершения; повторное завершение безопасно |
| Платформенные роли | Медицина | principal_ref, scope, valid_until, status | без отдельного активного grant запрос заканчивается 403 и audit event |
| Медицина | Аудит | actor, access result, scope, purpose, timestamp | каждый просмотр и отказ фиксируется; медицинское содержимое в payload не пишется |
| Медицинский документ | Ограничение | record_id, subject_id, limitation, action_scope | наружу передаётся только необходимый режим, не медицинское основание |
| Медицинский случай | Действия | case_id, incident_id, responsible_id, due_at, result, confirmation_ref | закрытие блокируется до выполнения всех действий и подтверждения |
| Медицина | Общие отчёты | отсутствует | медицинские таблицы намеренно не являются поставщиком общих KPI |
| Договоры | Первичка | contract_id, counterparty_id | документ без известного договора остаётся на проверке, а не получает ложную связь |
| Первичка | Финансы | payment_operation_id, amount_minor, counterparty_entity_id | связь создаётся только при совпадении суммы и контрагента |
| Комплектность | Задачи | check_id, missing_types, owner_id, automation_key | одна проверка создаёт одну задачу на недостающий комплект |
| Первичка | ЭДО | signature_status, edo_status | до подключения ЭДО используется только ручное подтверждение с основанием |
| Первичка | 1С | export_id, period, document_count, amount_minor, file_ref | пакет готовится локально; статус не выдаётся за импорт в 1С |
| Цель | KPI | goal_id, target, actual, forecast, source_ref | состояние объясняется планом, фактом и прогнозом |
| KPI | Инициатива | kpi_id, hypothesis, owner_id, dates | инициатива обязана объяснять, какой KPI и как она меняет |
| Инициатива | Проект | initiative_id, goal_id, owner_id, outcome | проект не существует без цели, владельца и ожидаемого результата |
| Проект | Финансы | budget_id, plan_minor, actual_minor | бюджет проекта связан с финансовым бюджетом; расход не имитирует банк |
| Проект | Событие | project_id, responsible_id, budget_minor, actual_minor | событие разделяет план проведения и измеримый результат |
| KPI | Отклонение/задача | kpi_id, variance, explanation, task_id, evidence, decision | закрытие без доказательства и явного решения запрещено |
| Внешняя система | Центр интеграций | source of truth, auth state, adapter version, checkpoint | live-статус только после проверенной передачи |
| Центр интеграций | Все бизнес-модули | connection_id, target_module, run_id, record_ref | blocked-run не создаёт бизнес-факт |
| Синхронизация | Журнал/аудит | correlation_id, counters, checkpoint, error | каждый запуск трассируется без раскрытия секрета |
| Интеграция | Конфликт/задача | conflict_id, two values, owner_id, automation_key | молчаливая перезапись запрещена; одна задача на конфликт |
| Доменные таблицы | Метрика | formula, grain, source tables, freshness, quality | показатель не существует без определения и provenance |
| Метрика/сигнал | AI-контракт | contract_id, inputs, allowed/forbidden, owner, auto-stop | модель не получает доменных прав |
| AI-контракт | Model run | version, snapshot_ref, confidence, explanation, cost | результат append-only и отделён от решения человека |
| Сигнал | Задача/решение | evidence, source refs, automation key, decision evidence | одно действие на сигнал; закрытие только человеком |
| AI-контракт | Opt-out | scope, reason, stop time, historical policy | новый run блокируется, базовый модуль работает дальше |
| Медицина | Общая аналитика/ИИ | отсутствует | медицинские записи и агрегаты намеренно не читаются |

Каждый переход получает стабильный идентификатор связи и audit event.
