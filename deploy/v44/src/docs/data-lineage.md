# Происхождение показателей

## Пример: чистый денежный поток апреля 2026

`Атлас ОДДС.xlsx → лист 2026 → строка «Чистый денежный поток» → столбец «Апрель» → 3 880 228,95 ₽ → карточка финансов`.

Качество: агрегат прочитан; банковские операции, договор и первичный документ не подключены. Поэтому показатель помечен как тестовый и не используется для реального решения.

## Пример: оплаты школы мая 2026

`Ежемесячные оплаты.xlsx → лист «школа май 2026» → 30 записей → обезличенные суммы оплат и остатков → платёжная дисциплина`.

ФИО и комментарии семей в snapshot не попали.

## Этап 4 — доказательный drill-down

`Атлас ОДДС → лист 2026 → ячейка/диапазон → financial_operation → статья + период → контрагент-ID → договор → документ → проект → юрлицо → объект → ЦФО → аудит`.

Пример апреля: `E54 → FIN-2026-04-OUT-* → Заработная плата → EMP-GROUP-T → PAYROLL-T → PAYROLL-T-2026 → PRJ-T-004 → ORG-T-001 → OBJ-T-002 → CFR-T-001`.

Ссылка `BANK-TEST-*` является только тестовой проекцией будущей банковской операции. Доступных выписок Точки/Альфа-Банка нет, поэтому интерфейс явно показывает границу и не называет эту ссылку банковским фактом.

Контрольные суммы для каждого месяца сверяют реестр с `строкой 2`, `строкой 34` и `строкой 111`. Дополнительный аудит выявил два самостоятельных расхождения исходного файла: детальные строки `E79:E85` не входят в пустую итоговую строку `E78`, а январская `B111` не равна `B2 + B34`. Оба случая сохранены в очереди сверки; исходный XLSX не исправлялся.

## Этап 5 — сквозной клиентский маршрут

`Первый клик CLICK-T-014 → yandex/cpc/school_2026 → CMP-T-001 → CR-T-011 → OFF-T-001 → FORM-T-SCHOOL → LEAD-T-014 → EMP-T-SALES-001 → CONSULT-T-014 → VISIT-T-014 → DOG-T-2026-014 → FAM-T-014 → CHD-T-014 → SVC-T-001 → ACR-CLIENT-T-014 → FIN-TEST-CLIENT-014 → LIFE-T-014`.

CRM, рекламные кабинеты, телефония и формы не предоставлены. Поэтому весь маршрут имеет `SYNTHETIC_SALES_TEST`; это тест доказуемости связей, а не реальный клиент или маркетинговая атрибуция. Финансовая операция находится в общем реестре, но исключена из периодов XLSX ОДДС и явно помечена синтетической.

## Этап 6 — контент до выручки

`PLAN-T-071 → PUB-T-071 → CLICK-T-071 → LEAD-T-071 → DOG-T-2026-071 → FIN-TEST-CONTENT-071 → 46 000 ₽ тестовой выручки`.

Атрибуция использует модель «первый клик · тест». Она не называется реальной, потому что `Продвижение.xlsx`, рекламные кабинеты и API социальных сетей не предоставлены. Финансовая операция хранит `source_system=SYNTHETIC_CONTENT_TEST` и не входит в факт ОДДС.

## Этап 7 — от программы до улучшения

`PRG-T-012 v4 → EMP-T-032 → GRP-T-3A → LES-T-3A-0821 → ATT-T-014 → PROG-T-014 (86, рост) → FDB-T-014 (5/5) → рекомендация «парное объяснение» → идемпотентная методическая задача`.

Все карточки этого маршрута синтетические и обезличенные. Родительский scope `FAM-T-014` отсекает чужих детей и семейные коммуникации; педагогический scope `EMP-T-032` отсекает неназначенные группы. Медицинские данные не входят в запрос или ответ образовательного API.

## Этап 8 — жизненный цикл сотрудника

`VAC-T-008 → CANDREC-T-008 → INTV-T-008 → EMP-T-052 → DOG-EMP-T-052 → POS-T-TEACHER → ставка 95 000 ₽ → ACC-TASKS-052 / ACC-EDU-052 → задача адаптации → DEV-T-052-01 → FIN-TEST-PAYROLL-052 → DEV-T-052-02 → увольнение 2026-08-15 → отзыв доступов`.

Кандидат, сотрудник и денежное событие синтетические. Отзыв доступов проверяется отдельно от сохранности истории: задача адаптации, договор, обучение, оценка и выплата продолжают читаться после увольнения.

## Этап 9 — юридический сигнал до задачи

`CTR-T-044 → LCON-T-044 → DOG-T-2026-044 → APP-T-044 → ZONE-T-044-01 → обязательный ACT-T-044 со статусом «Отсутствует» → SIG-LGL-T-002 → LEGAL_SIGNAL:SIG-LGL-T-002`.

Отдельно проверяются подпись, срок 2026-09-02, лимит 500 000 ₽ против тестового расхода 540 000 ₽, реквизиты и закрывающий пакет. Источник полностью синтетический; ЭП/ЭДО не подключены.

## Этап 10 — закупка до ОПиУ

`REQ-T-088 → согласование EMP-T-004 → OFFR-T-088-22 → SUPREC-T-022 → LCON-SUP-T-022 / DOG-SUP-T-022 → ORD-T-088 → DLV-T-088 → ITEM-T-LAPTOP-088 → ASSET-T-088-01 → ACT-REQ-T-088 → FIN-TEST-PROC-088 → Расходы ОПиУ`.

Три предложения сравниваются по цене, сроку, гарантии и качеству. Рынок и платёж синтетические; банковской операции и внешнего каталога цен нет.

## Этап 11 — питание до прибыльности

`REQ-T-FOOD-021 → заказ/поставка → продукт → BATCH-T-021-02 → срок годности → TTK-T-014 → ингредиенты/нормы → PROD-T-0821 → смены → SHIP-T-0821-01 → потребление/возврат/списание → FIN-TEST-FOOD-COST-0821 + FIN-TEST-FOOD-REV-0821 → прибыль/маржа`.

`PRJ-T-KITCHEN` и `CFR-T-KITCHEN` являются явной границей центра результата. Источник этапа — `SYNTHETIC_FOOD_TEST`; реальный складской, кассовый и санитарный факт отсутствует.

## Этап 12 — безопасность до следующей проверки

`SAFE-EQ-T-001 → OBJ-T-001 → SAFE-CHK-T-090 → SAFE-FLT-T-031 → SAFETY_FAULT:SAFE-FLT-T-031 → SUP-T-SAFE-001 → SAFE-REP-T-031 → ACT-SAFE-T-031 → FIN-TEST-SAFE-031 → SAFE-NEXT-T-031`.

Источник `SYNTHETIC_SAFETY_TEST` явно отделён от реальной телеметрии. Система не заявляет подключение СКУД, камер, датчиков или банка; схема, журнал, акт и платёж — тестовые ссылки.

## Этап 13 — изолированная медицинская история

`аутентифицированный пользователь → ROLE:MEDICAL → MEDICAL_FULL_SYNTHETIC → audit medical.records_viewed → MED-DOC-T-CH-014 → MED-LIMIT-T-014`.

`MED-CASE-T-021 → MED-INC-T-021 → MED-ACT-T-021-01/02 → результат → MED-CONF-* → закрытие → audit`. Для общей роли маршрут заканчивается на 403 и `medical.access_denied`; медицинская запись не возвращается.

## Этап 14 — первичка до финансовой операции

`ACC-INV-T-031 → ACC-LINK-T-031 → ACC-ACT-T-031 → DOG-SUP-T-SAFE-001 → FIN-TEST-SAFE-031 → source_system=SYNTHETIC_SAFETY_TEST`.

Комплектность кухни: `FIN-TEST-FOOD-COST-0821 → ACC-COMP-T-FOOD → missing=[Счёт] → ACCOUNTING_MISSING:ACC-COMP-T-FOOD`. Выгрузка: `документы 2026-08 → ACC-EXP-T-1C-0826`; реальной передачи в 1С нет.

## Этап 15 — от цели до решения

`GOAL-T-2026-01 → KPI-T-FAMILY-01 → INIT-T-014 → STR-PRJ-T-014 → PROJECT:STR-PRJ-T-014:MILESTONE:1 → BUD-2026-08-OUT`.

Результат события: `STR-PRJ-T-014 → EVENT-T-071 → участники → STR-RES-T-071`. Контроль отклонения: `KPI-T-FAMILY-01 → DEV-T-KPI-01 → STRATEGY_DEVIATION:DEV-T-KPI-01 → доказательство → решение`. Все факты этапа помечены `SYNTHETIC_STRATEGY_TEST`.

## Этап 16 — от источника до подтверждённой записи

Успешная проверка: `INT-T-D1 → auth active → adapter d1-core@1 → INT-RUN-T-D1-01 → checkpoint D1:health:ok → log health.verified → verified_transfer=true`.

Заблокированный внешний запуск: `INT-T-ALFACRM → auth missing → INT-RUN-T-CRM-PREFLIGHT → status=Заблокировано → log auth.missing`; клиентская запись не создаётся. Расхождение: `INT-T-ODDS → INT-RUN-T-ODDS-01 → INT-CNF-T-ODDS-01 → INTEGRATION_CONFLICT:* → решение + evidence`.

## Этап 17 — от факта до человеческого решения

Финансовый факт: `Атлас ОДДС.xlsx → financial_operations (XLSX_AGGREGATE) → MET-T-CASH → дашборд`. Прогноз: `FC-T-001..006 → TEST-RULES-v0.1 → AI-RUN-T-CASH-01 → AI-SIG-T-CASH → explanation + confidence → ANALYTICS_SIGNAL:* → human decision + evidence`.

Отказ: `AI-CONTRACT-* → AI-OPTOUT-* → contract status=Отключён → run blocked`; исходные модульные записи не удаляются, а новые признаки перестают поступать в сценарий.
