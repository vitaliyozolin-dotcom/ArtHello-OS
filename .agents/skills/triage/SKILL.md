# Триаж бэклога

Не редактировать `BACKLOG.md` без явной просьбы.

1. Прочитать `BACKLOG.md` целиком вместе с легендой.
2. Проверить `[x]` и `[~]` по коду, тестам, миграциям, документированным reviewer verdicts и доступному CI. Файл существует не означает, что gate пройден.
3. Найти открытое уже реализованное, закрытое деградировавшее, ссылки на исчезнувшие файлы и дубли `REFACTORING_PLAN.md`.
4. Не закрывать пункт с условием независимого Reviewer PASS, пока доказательство PASS не найдено.
5. Предложить 1–3 следующих шага в порядке: security/доказуемость P0, надёжность P1, операционная модель, финансовая правда, UI P2.
6. Не придумывать новые задачи: каждое предложение привязать к находке, тесту или действующему решению.

Выдать расхождения в таблице, кандидаты на закрытие с требуемым evidence, stale/duplicates и следующие шаги. Для фактов использовать `path:line` либо вывод команды.
