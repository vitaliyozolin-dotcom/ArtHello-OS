# Доменная модель

Проверять факты по `lib/db/src/schema/*.ts` и barrel `index.ts`; затем `DATA_COVERAGE.md`, `docs/integration_contracts.md`, `MASTER_BOOK.md`, `DECISIONS.md`. Банк — правда о движении денег, AlfaCRM — операционная правда; не переносить авторитет между зонами.

1. Выписать затронутые таблицы, ключи, FK и уникальности с `path:line`; проверить реэкспорт схем.
2. Проверить инварианты: слабый сигнал создаёт manual-review candidate, но не автослияние семьи; leads отделены от students; нормализованные записи наследуют raw+batch provenance; raw append-only; деньги в minor units; неутверждённое остаётся unresolved; финансовые сущности привязаны к юрлицу.
3. Описать назначение, ключи, связи, источник/provenance каждого поля и поведение при отсутствии данных.
4. Определить последствия для миграций, API/UI, permissions и empty states. При миграции применить `$migration-check`.
5. Для нового или изменённого доменного правила предложить текст нового D-решения со следующим подтверждённым свободным номером; не редактировать решение без просьбы.

Выдать мини-спецификацию: было → станет, связи, инварианты, provenance, последствия и вопросы, неразрешимые по репозиторию.
