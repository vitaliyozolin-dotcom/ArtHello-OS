# TDD ArtHello OS

Использовать существующий `node --test` и `*.test.mjs`; не добавлять Jest/Vitest. Тесты размещать рядом с существующими suites. Для DB-логики переиспользовать PGlite helpers; реальный PG16 требует `TEST_DATABASE_URL`.

1. Red: добавить минимальный поведенческий тест и выполнить его. Убедиться, что он падает по ожидаемой причине; сохранить существенный вывод.
2. Green: внести минимальную реализацию и показать зелёный результат целевого теста.
3. Refactor: улучшить код без расширения scope; повторить целевые тесты и `pnpm run typecheck`.
4. Запустить агрегатный gate, который действительно включает новый тест. Если `test:full` его не включает, выполнить suite явно.

Regex/readFile проверки исходника допустимы как существующие security anti-drift ratchets, но не заменяют поведенческий тест новой логики. Для финансов использовать synthetic minor units и инварианты, без реальных ставок. Для identity сначала сделать characterization tests найденных вариантов. Покрывать важные deny/missing-env/error ветки и не помещать реальные PII в fixtures.

В отчёте перечислить файлы, red и green команды/результаты, агрегатные гейты и непроверенное.
